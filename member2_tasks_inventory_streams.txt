=================================================
MEMBER 2 — PRODUCT & INVENTORY SERVICE + STREAM PROCESSING
=================================================

GLOBAL CONTEXT (read before starting any task):
- Tech stack: Java 21, Spring Boot 3.x, H2, Spring Cloud Stream / spring-kafka,
  Kafka Streams
- This service's own database: inventory_db
- Base package: com.ecommerce.inventory
- Kafka topics used: "order-events" (this service CONSUMES from it),
  "inventory-events" (this service PUBLISHES to it)
- Event envelope format for ALL Kafka messages (both topics):
  {
    "eventType": "OrderCreatedEvent",
    "eventId": "<uuid>",
    "timestamp": "<ISO-8601>",
    "payload": { ... }
  }
- This service runs on port 8082
- IMPORTANT: "available stock" = stock_quantity - reserved_quantity.
  Reserving = increment reserved_quantity. Releasing (on cancel) = decrement it.
  stock_quantity itself is never changed by these flows in this project's scope.

FILE 9: OrderEventConsumer.java
--------------------------------------------------
Package: com.ecommerce.inventory.event.consumer
Annotations: @Component
Constructor-inject: ProductService, InventoryEventProducer, ObjectMapper

Method: @KafkaListener(topics = "order-events", groupId = "inventory-service")
  onMessage(String rawMessage)
  Logic:
    1. Parse rawMessage to read "eventType" field
    2. IF eventType == "OrderCreatedEvent":
       - parse payload into OrderCreatedPayload
       - call productService.reserveStock(payload.orderId, payload.items)
         (this method internally decides success/failure and calls the
         producer itself — see below)
    3. IF eventType == "OrderCancelledEvent":
       - parse payload into OrderCancelledPayload
       - call productService.releaseStock(payload.items)
    4. IF eventType == "OrderConfirmedEvent" or "OrderRejectedEvent": ignore
       (this service does not act on those)

--------------------------------------------------
MODIFY: ProductService.java — add 2 methods
--------------------------------------------------
Constructor-inject (add): InventoryEventProducer

Method: reserveStock(String orderId, List<OrderItemEventDto> items) -> void
  Logic:
    1. For each item, load the Product by productId (UUID.fromString(item.productId))
    2. Check: for EVERY item, is (stockQuantity - reservedQuantity) >= item.quantity?
    3. IF all items have sufficient available stock:
       - for each item: product.reservedQuantity += item.quantity; save
       - build InventoryReservedPayload(orderId, items)
       - inventoryEventProducer.publish("InventoryReservedEvent", payload)
    4. IF any item is insufficient:
       - do NOT reserve ANY items (all-or-nothing — a partial reservation
         would leave inconsistent state)
       - build list of InventoryUnavailableItemDto for the insufficient ones
         (include requested vs available amounts)
       - build InventoryRejectedPayload(orderId, "INSUFFICIENT_STOCK", unavailableItems)
       - inventoryEventProducer.publish("InventoryRejectedEvent", payload)

Method: releaseStock(List<OrderItemEventDto> items) -> void
  Logic:
    1. For each item, load Product by productId
    2. product.reservedQuantity -= item.quantity (never let it go below 0 —
       clamp to 0 if a negative would occur, and log a warning if that happens
       since it indicates a data inconsistency)
    3. Save each updated product
    (no event is published after release — this is a terminal step)

FILE 1: RevenueStreamsTopology.java
--------------------------------------------------
Package: com.ecommerce.inventory.streams
Annotations: @Configuration

Bean method: @Bean
  public KStream<String, String> revenueStream(StreamsBuilder streamsBuilder)

  Logic (pseudocode — exact Java syntax depends on your Kafka Streams /
  Spring Cloud Stream version, confirm against the version in pom.xml):
    1. KStream<String, String> source = streamsBuilder.stream("order-events");
       (using String values and manually parsing JSON is simplest here;
       avoid a custom JSON Serde unless the team is comfortable with it)
    2. Filter: only rows where the JSON's "eventType" field equals
       "OrderCreatedEvent" (parse with a JSON library like Jackson's
       ObjectMapper inside the filter's lambda)
    3. Extract totalAmount (a double) from each message's payload
    4. groupBy a constant key (e.g., "TOTAL") so all messages aggregate
       into a single running sum
    5. aggregate:
       - initializer: () -> 0.0
       - adder: (key, extractedAmount, currentTotal) -> currentTotal + extractedAmount
       - Materialized.as("revenue-store")   <-- exact store name, referenced
         in RevenueQueryService.java below, must match exactly
    6. Return/build the resulting KTable (the topology auto-runs once the
       Spring context starts, no explicit .start() call needed with
       Spring Cloud Stream/Kafka Streams binder — confirm setup per your
       chosen library's docs)

IMPORTANT: If using Spring Cloud Stream's Kafka Streams binder instead of
raw Kafka Streams API, the equivalent is a @Bean of type
java.util.function.Consumer<KStream<String,String>> named appropriately,
configured via spring.cloud.stream.bindings in application.yml. Confirm
with the team which approach (raw Kafka Streams vs Spring Cloud Stream
binder) you're using BEFORE starting this file, since the class structure
differs. The pseudocode above assumes raw Kafka Streams API for clarity.

--------------------------------------------------
FILE 2: RevenueQueryService.java
--------------------------------------------------
Package: com.ecommerce.inventory.streams
Annotations: @Service
Constructor-inject: StreamsBuilderFactoryBean (Spring Kafka's wrapper for
accessing the running KafkaStreams instance)

Method: getTotalRevenue() -> Double
  Logic:
    1. KafkaStreams streams = streamsBuilderFactoryBean.getKafkaStreams();
    2. ReadOnlyKeyValueStore<String, Double> store = streams.store(
         StoreQueryParameters.fromNameAndType("revenue-store",
         QueryableStoreTypes.keyValueStore()));
    3. Double total = store.get("TOTAL");
    4. Return total != null ? total : 0.0;
