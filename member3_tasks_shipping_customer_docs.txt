MEMBER 3 — SHIPPING SERVICE + CUSTOMER SERVICE + TESTING/DOCS
=================================================

GLOBAL CONTEXT (read before starting any task):
- Tech stack: Java 21, Spring Boot 3.x, H2, Spring Cloud Stream / spring-kafka
- Shipping Service database: shipping_db (base package: com.ecommerce.shipping)
- Customer Service database: customer_db (base package: com.ecommerce.customer)
  NOTE: These are TWO SEPARATE Spring Boot services/modules, each with their
  own pom.xml, application.yml, and port — not one combined app.
- Kafka topics: Shipping Service CONSUMES from "order-events" only.
  It does NOT publish any Kafka events (confirmed decision).
- Customer Service does NOT use Kafka at all (confirmed decision — fully
  decoupled, plain REST CRUD only).
- Event envelope format for messages on "order-events":
  {
    "eventType": "OrderConfirmedEvent",
    "eventId": "<uuid>",
    "timestamp": "<ISO-8601>",
    "payload": { ... }
  }
- Shipping Service runs on port 8083
- Customer Service runs on port 8084

FILE 7: ShipmentService.java

Package: com.ecommerce.shipping.service
Constructor-inject: ShipmentRepository

Method 1: getShipmentByOrderId(UUID orderId) -> ShipmentResponse
  Logic:
    1. shipmentRepository.findByOrderId(orderId)
    2. If empty, throw new ShipmentNotFoundException(orderId)
       (this will become a 404, which Member 1's client treats as
       "no shipment yet" — this is expected/correct behavior, not a bug)
    3. Map to ShipmentResponse, return

Method 2: updateStatus(UUID orderId, String newStatus) -> ShipmentResponse
  Logic:
    1. shipmentRepository.findByOrderId(orderId), throw
       ShipmentNotFoundException if absent
    2. Validate newStatus is one of: "CREATED","DISPATCHED","IN_TRANSIT",
       "DELIVERED","CANCELLED" — else throw InvalidShipmentStatusException(
       "Unknown status: " + newStatus)
    3. Set shipment.status = newStatus, updatedAt = Instant.now()
    4. Save, map to ShipmentResponse, return
    (No transition-order validation required for this project's scope —
    e.g., you CAN jump straight from CREATED to DELIVERED manually via this
    endpoint for testing purposes. Keep it simple.)

Method 3 (used internally by Task 3.2's Kafka consumer):
  createShipment(UUID orderId) -> Shipment
  Logic:
    1. Create new Shipment: id=random UUID, orderId=orderId, status="CREATED",
       createdAt=updatedAt=Instant.now()
    2. Save and return the entity

Method 4 (used internally by Task 3.2's Kafka consumer):
  cancelIfNotDispatched(UUID orderId) -> void
  Logic:
    1. shipmentRepository.findByOrderId(orderId)
    2. IF not found: do nothing (log at info level — order was cancelled
       before any shipment existed, which is a normal/expected case)
    3. IF found AND status == "CREATED": set status = "CANCELLED", save
    4. IF found AND status is anything else (DISPATCHED, IN_TRANSIT,
       DELIVERED): do nothing, log a warning (this shouldn't normally
       happen since Member 1's cancelOrder() checks shipment status
       first, but this method must not throw an exception — Kafka
       consumers should not crash on this case)

TASK 3.2 — Kafka Consumer: React to Order Confirmed/Cancelled Events
=================================================

GOAL:
Consume OrderConfirmedEvent to create a shipment, and OrderCancelledEvent
to cancel a shipment if it hasn't been dispatched yet.

DEPENDS ON: Task 3.0 (Kafka running) and Task 3.1 complete.

--------------------------------------------------
FILES TO CREATE
--------------------------------------------------
1. src/main/java/com/ecommerce/shipping/event/dto/OrderConfirmedPayload.java
2. src/main/java/com/ecommerce/shipping/event/dto/OrderCancelledPayload.java
3. src/main/java/com/ecommerce/shipping/event/dto/OrderItemEventDto.java
4. src/main/java/com/ecommerce/shipping/event/consumer/OrderEventConsumer.java

FILES TO MODIFY:
- application.yml (add Kafka consumer config)

NOTE ON DUPLICATE DTOs: these are THIS SERVICE's own local copies. Field
names must match EXACTLY what Member 1 publishes:
  OrderConfirmedEvent payload: { orderId, customerId, items: [{productId, quantity}] }
  OrderCancelledEvent payload: { orderId, items: [{productId, quantity}], previousStatus }
(Shipping Service only actually needs the orderId field from either payload
 — but define the full DTO shape anyway so parsing doesn't break if more
 fields are added later.)

--------------------------------------------------
FILE 1: OrderConfirmedPayload.java
--------------------------------------------------
Package: com.ecommerce.shipping.event.dto
Fields: String orderId, String customerId, List<OrderItemEventDto> items

--------------------------------------------------
FILE 2: OrderCancelledPayload.java
--------------------------------------------------
Package: com.ecommerce.shipping.event.dto
Fields: String orderId, List<OrderItemEventDto> items, String previousStatus

--------------------------------------------------
FILE 3: OrderItemEventDto.java
--------------------------------------------------
Package: com.ecommerce.shipping.event.dto
Fields: String productId, Integer quantity

--------------------------------------------------
FILE 4: OrderEventConsumer.java
--------------------------------------------------
Package: com.ecommerce.shipping.event.consumer
Annotations: @Component
Constructor-inject: ShipmentService, ObjectMapper

Method: @KafkaListener(topics = "order-events", groupId = "shipping-service")
  onMessage(String rawMessage)
  Logic:
    1. Parse rawMessage to read "eventType" field
    2. IF eventType == "OrderConfirmedEvent":
       - parse payload into OrderConfirmedPayload
       - call shipmentService.createShipment(UUID.fromString(payload.orderId))
    3. IF eventType == "OrderCancelledEvent":
       - parse payload into OrderCancelledPayload
       - call shipmentService.cancelIfNotDispatched(UUID.fromString(payload.orderId))
    4. IF eventType is anything else ("OrderCreatedEvent", "OrderRejectedEvent"):
       ignore (this service does not act on those)

--------------------------------------------------
MODIFY: application.yml — add:
--------------------------------------------------
spring:
  kafka:
    bootstrap-servers: localhost:9092
    consumer:
      group-id: shipping-service
      key-deserializer: org.apache.kafka.common.serialization.StringDeserializer
      value-deserializer: org.apache.kafka.common.serialization.StringDeserializer
      auto-offset-reset: earliest

--------------------------------------------------
ACCEPTANCE CRITERIA
--------------------------------------------------
[ ] Publishing an OrderConfirmedEvent (matching the contract) creates a new
    shipment row with status="CREATED" for that orderId
[ ] Publishing a second OrderConfirmedEvent for the SAME orderId does not
    crash (decide: either ignore duplicates, or let it fail gracefully —
    document whichever behavior you chose as a code comment)
[ ] Publishing an OrderCancelledEvent for an order whose shipment is still
    "CREATED" updates that shipment's status to "CANCELLED"
[ ] Publishing an OrderCancelledEvent for an order with NO shipment at all
    does not throw an exception or crash the consumer
[ ] GET /shipments/{orderId} reflects all of the above changes correctly

--------------------------------------------------
IMPLEMENTATION STEPS
--------------------------------------------------
1. Create the 3 event DTO classes (match Member 1's contract exactly)
2. Create OrderEventConsumer.java
3. Add Kafka consumer config to application.yml
4. Test: manually publish an OrderConfirmedEvent JSON to the "order-events"
   topic via kafka-console-producer, verify a shipment is created; then
   publish an OrderCancelledEvent for the same orderId, verify it cancels
